# 系統現況架構與產學需求差距確認表

**盤點基準日：2026 年 10 月 2 日**  
**用途：**供產學／食物銀行需求會議確認目前系統範圍、實作狀態及待決策事項。  
**盤點依據：**目前程式碼、資料庫 SQL 快照、安裝指南，以及 2026/09/16 會議紀錄和 2026/09/30 系統變更紀錄。

> 本表描述的是儲存庫中可查證的現況，不代表已部署環境或正式驗收結果。尚未取得產學方正式需求規格，因此「待確認」不等於「不符合」；請於會議確認預期流程、驗收標準和優先順序後，再判定差距。

## 一、系統架構總覽

| 架構層 | 目前組成 | 職責／資料流 | 現況與邊界 |
|---|---|---|---|
| 使用者端 | 瀏覽器；食物銀行職員、一般會員（Rider）、企業會員 | 登入後依權限使用管理、捐贈、配送、活動、獎勵及報表頁面 | 響應式頁面；即時位置分享需使用者授權瀏覽器定位，部署需 HTTPS（localhost 除外）。 |
| 展示層 | PHP 頁面模板、共用 CSS/JavaScript | 表單、列表、訂單追蹤及管理介面 | PHP 伺服器端渲染為主；目前未見獨立 SPA 前端或完整前後端 API 分層。主要資產位於 `public/assets/`。 |
| Web 入口／流程控制 | `public/index.php` | 處理登入、註冊、手機驗證、密碼重設、頁面路由、權限檢查，以及配送定位／距離計算 action | 單一前端控制器；大部分頁面由 `src/views/` 載入。沒有獨立 controllers 目錄。 |
| 身分驗證與授權 | PHP Session、`AuthService`、`PermissionModel`、CSRF helper | 以 `foodbank_staff`、`member` 及會員類型決定頁面／操作權限；支援個人權限覆寫 | 權限表包含於 SQL 快照及遷移檔；需在目標資料庫完成匯入，才可確認部署環境可正常使用。 |
| 業務邏輯 | `src/models/`、`src/services/`、`src/helpers/` | 管理捐贈、配送、活動、物資分類、通知、獎勵／興毅幣及會員權限 | 採 PHP 模型與服務分層，但部分頁面本身亦直接處理表單與資料庫操作。 |
| 資料層 | MySQL／MariaDB 相容資料庫；MySQLi | 保存會員、捐贈及物資明細、配送及位置、活動、通知、點數／兌換、權限等資料 | 主快照為 `database/shinigyi_foodbank (4).sql`；資料庫實際匯入及既有資料遷移尚未確認成功。 |
| 外部服務 | OpenStreetMap Nominatim／OSRM、OpenStreetMap 圖資、Google Maps 導航連結、CDN 資產 | 地址定位與路徑距離估算、地圖檢視、外部導航、前端字型／圖示／QR 掃描資產 | 距離估算依賴伺服器可連外及 PHP cURL；使用者開啟地圖或外部導航時會離開系統至第三方服務。 |
| 執行／部署環境 | 安裝文件指定 Apache、PHP 7.4+、MySQL 5.7+；文件以 XAMPP 為例 | 提供 PHP 網站與資料庫服務 | 以上為文件記載的需求，並非本次對實際伺服器版本或正式環境所做的檢測。 |

### 主要資料流

| 流程 | 現行路徑 |
|---|---|
| 企業會員捐贈 | 企業會員 → 物資捐贈表單 → 捐贈主資料及物資明細 → 食物銀行審查／配送設定 → 訂單追蹤 |
| Rider 配送 | 一般會員承接配送任務 → 取貨確認／配送狀態更新 → 可選擇分享即時位置 → 完成配送 |
| 食物銀行管理 | 職員登入 → 審查捐贈、管理配送／活動／會員／物資分類 → 查詢報表及通知 |
| 企業永續資訊 | 企業會員捐贈及配送資料 → 永續報告頁；報告範圍及計算口徑仍需與需求方確認 |

## 三、產學需求對照與待確認差距

狀態定義：**已見於程式碼**＝有相關頁面／邏輯；**部分符合／待驗收**＝僅實作部分或缺正式驗收；**待需求方決策**＝目前沒有足夠規格判斷符合與否；**文件／資料不一致**＝程式、文件或 SQL 快照需先核對。

| # | 需求主題（依現有會議紀錄） | 儲存庫中觀察到的現況 | 初步狀態 | 需與產學方確認／建議驗收問題 |
|---|---|---|---|---|
| 1 | 系統定位以物資媒合與配送為主 | 現行頁面及模型集中於捐贈、審查、配送任務與訂單追蹤 | 已見於程式碼；範圍待確認 | 是否以捐贈至食物銀行的配送閉環為第一階段唯一核心？哪些功能應列為本期範圍外？ |
| 2 | 志工／Rider 接單後導航 | 配送頁提供 Google Maps 導航連結；非系統內地圖導航，也未見路線逐步導引 | 部分符合／待驗收 | 外部導航連結是否足夠？導航需呈現取貨點、送達點、多站排序，或路線最佳化嗎？ |
| 3 | 配送期間物資狀態追蹤 | 配送模型及頁面包含待處理／已承接／已取貨／配送中／送達等流程狀態；訂單頁顯示進度 | 已見於程式碼；狀態定義待確認 | 請確認各狀態名稱、可由哪個角色更新、更新時點、是否需要照片／簽收／時間戳作為驗收證明。 |
| 4 | 即時配送位置 | 有 `delivery_locations` 及定位 action；安裝文件記載經使用者同意後每 10 秒更新，顧客可選擇開啟 OpenStreetMap | 部分符合／待驗收 | 是否需要持續追蹤、更新頻率、保留多久、哪些角色可看？無定位或網路中斷時的替代流程為何？ |
| 5 | 物資分類及捐贈紀錄 | 有物資分類管理、`donation_items` 明細、配送地址及配送紀錄相關欄位 | 已見於程式碼；資料完整性待驗收 | 分類由誰維護？需要記錄哪些交接位置、照片、重量、效期、數量或驗收人？目前欄位是否足夠？ |
| 6 | 一筆捐贈包含多項物資 | 現行捐贈表單含 `item_name[]` 等陣列欄位；SQL 有 `donation_items` 明細表 | 程式碼可見多筆輸入；端到端待驗收 | 確認是否要支援多品項、不同數量／效期／規格、拆分到不同子單；用測試捐贈驗證提交、審查、拆單、追蹤及報表全流程。 |
| 7 | 志工管理介面與資料 | 有一般會員管理頁面／路由及使用者資料；一般會員同時承擔 Rider 功能 | 部分符合／角色定義待確認 | Rider 資格、審核、可服務區域、可配送時段、車種、訓練／同意紀錄是否需管理？「一般會員」與「Rider」是否應是不同資格？ |
| 8 | 永續報表提供捐贈企業查看 | 有企業端永續報告頁；2026/09/30 紀錄提到完成配送趟次、捐贈重量、配送里程及避免浪費估算 | 已見於程式碼／計算口徑待確認 | 報表要涵蓋哪些供應鏈階段？碳排／避免浪費的係數、公式、資料來源、期間、匯出格式及免責說明為何？ |
